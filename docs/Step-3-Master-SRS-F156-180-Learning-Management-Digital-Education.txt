Outcome and actors
Item
Entry
Outcome and trigger
A learner can discover a course, enrol, learn (content / live / recorded / labs / practice / coding / exam prep), get help (AI Tutor / teacher), be assessed, earn micro-credentials / certificates, and track progress — and a teacher / coordinator / admin can create, publish, manage, and monitor all of it. Trigger: user opens LMS Home from the Admiezo ERP dashboard. Successful end state: learner progress, assessment results, micro-credentials, and certificates are visible and consistent across Home, My Courses, Progress, and Certificate screens.
Actors and scope
Learner • Teacher / Author / Reviewer • Teaching Assistant (TA) • Coordinator • Librarian • Translator / Reviewer • Seller • Admin. Scope: one tenant / institution, one campus at a time. A user sees ONLY the courses / cohorts / content they are enrolled in or assigned to, except public catalogue / marketplace browse.
Dependencies
Admission — enrolment source for admitted learners; Identity & Access — login + roles; Notification — announcements / notifications; Document Storage — content / lecture / library files. If a dependency is unavailable, the dependent screen shows Unavailable with a recovery path.

Login credentials — demo / staging ONLY
For DEMO / STAGING review only. MUST NOT be used as real production credentials, MUST NOT be committed as real secrets, MUST be replaced by Identity & Access (Entra / SSO) before production. Who comes under each login is stated.

AI Assistant — General + Lesson Mode (F.163 / F.157)
Student lesson page → LMS backend checks access, retrieves content, calls API provider → summary / answer appears IN the lesson page. Modules are in the left bar; clicking a module shows its sub-features inside that module. User-friendly UI.
Requirement ID
Required behavior
Rules
F-REQ-AI-01
AI Assistant has exactly two modes: General questions (default) and Lesson mode.
Mode switch clears previous result; no stale response after mode/lesson change.
F-REQ-AI-02
General mode: user asks a question with no lesson text; assistant answers from the AI provider’s model knowledge.
No live internet search. No conversational memory. Each request independent.
F-REQ-AI-03
Lesson mode: user pastes / lesson page supplies lesson content; assistant generates a summary of THAT lesson, or answers a question about THAT lesson.
Answer ONLY from supplied lesson. Provide a supporting quote. Acknowledge when lesson does not contain enough information.
F-REQ-AI-04
Summary / answer appears INSIDE the lesson page (Lesson mode) / inside the assistant panel (General mode) — never as a new tab or download.
Displayed safely as text, never as raw HTML.
F-REQ-AI-05
Backend checks access before calling the API provider: user must be enrolled / assigned to the lesson’s course. If not, show “You do not have access to this lesson” and make NO provider call.
SEC-01; access check is server-side, never browser-only.
F-REQ-AI-06
Backend retrieves lesson content, calls the API provider, returns generated text or a readable error.
Provider key / model live ONLY in backend config (backend/.env in current build), never in browser JavaScript.
F-REQ-AI-07
Limits: lesson text max 60,000 characters; question max 2,000 characters. Over limit → readable error, no provider call.
Validation is server-side.
F-REQ-AI-08
Duplicate submissions are disabled while waiting. Changing mode or lesson clears the previous result.
Stale-response guard: older response after a change MUST NOT appear.
F-REQ-AI-09
API provider setting: leave a single, clearly-marked place in the backend code / config to paste the API key + model, so changing provider / key / model does not require a code change.
Current build: backend/.env (API key + model), reloaded on every request. Production: config / secret store — see LLD.
F-REQ-AI-10
Generated answers are shown as generated and need checking. Teacher Tutor Review can flag / review tutor answers.
AI-DISC-01.
