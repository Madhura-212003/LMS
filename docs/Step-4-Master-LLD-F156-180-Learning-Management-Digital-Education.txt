  │  LMS Home → Left-bar modules → Sub-features inside module
  │  Course Viewer / Lesson page + AI Assistant inside lesson page
  │
  │  HTTPS / JSON (Django Ninja APIs, Entra JWT)
  ▼

  │  • LMS APIs: courses, content, cohorts, enrolment, assignments, quizzes,
  │    activities, coding, labs, skills, exam packs (Competitive / NEET / JEE /
  │    UPSC / Placement), credentials, marketplace, notifications
  │  • Access check: enrolled / assigned? (server-side, never browser-only)
  │  • AI Service: builds prompt, calls API provider, returns text or readable error
  │  • AI Config: ONE place to paste API key + model — env / secret store,
  │    reloaded without a code change (see §5.3)
  ▼
PostgreSQL 16 (Azure) — Section F entities (§6)  •  Document Storage — content / lecture / library files
  │
  ▼

  │  (key + model live ONLY in backend config, never in browser JavaScript)
  ▼
Generated text → Backend → Lesson page → displayed safely as text (escaped)

1. Global implementation — applies to every Section F screen
SRS rule
Implementation
F-REQ-G01 Left-bar modules
Layout component <LMSLeftBar>: Section F modules (icon + name + active state). State: activeModule + activeSubFeature. Click module → set activeModule, render its sub-features INSIDE the module panel (no top-level navigation). Mobile: collapsed, hamburger button opens drawer. Route: /lms/[module]/[subFeature]. Active state from route.
F-REQ-G02 Visibility
Every Section F API query filters by: user_id + role + tenant/campus. Learner: enrolled/assigned only. Teacher: assigned courses only. Admin/Coordinator: campus scope. Public catalogue / marketplace browse: published courses only, no enrolment filter. Filter is in the QUERY (Django ORM), not in the UI.
F-REQ-G03 Lists
Shared <ListPage>: search (debounced, server-side), filter (status / subject / level / language), sort (title / date / progress), pagination (page size 20, cursor). Empty state: “No [items] yet” + primary action (e.g. Browse Catalogue).
F-REQ-G04 Feedback
Shared <AsyncButton> + <Toast>: Loading (button disabled + spinner) → Success (toast “X saved” + list/detail refresh) / Failure (toast with readable message + what to do next). No silent writes.
F-REQ-G05 Delete guard
Delete action: if dependents exist (progress / submissions / credentials / enrolments) → confirm dialog listing dependents → on confirm, soft-delete (is_deleted=true, deleted_at, deleted_by) + audit entry. Hard delete only by admin migration, never from UI.
F-REQ-G06 AI disclosure
AI Tutor / AI Assistant responses render with a “Generated by AI — please check” label above the text. Teacher Tutor Review can flag.
F-REQ-G07 Page memory (current build)
In the current as-built assistant, lesson + answers are page state only. In production, lesson content comes from the lesson store (§6) via the access-checked API (§5); chat history is NOT stored unless F-OPEN-08 is resolved to store it.

Implementation
LMS Home
Route /lms/home. Layout: <LMSLeftBar> + main. Main regions: Continue Learning (cards) • Upcoming classes • Due assignments / quizzes • Notifications • Insights (per role). Breakpoints: desktop 3-col cards, tablet 2-col, mobile 1-col + collapsed left bar. Data: GET /api/lms/home → { continue_learning[], upcoming_classes[], due_items[], notifications[], insights{} }. States
Loading: skeleton cards. Empty (no enrolment): “No courses yet” + Browse Catalogue → Course Catalogue. Unavailable: dependency error + Retry.
